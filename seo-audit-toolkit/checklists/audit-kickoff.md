# Audit Kickoff

Complete before Part 1 of the framework. Skipping this is how an audit ends up producing
confident findings from incomplete data.

## Access

- [ ] Search Console — verified access to the correct property, and the property type
      (domain versus URL prefix) confirmed
- [ ] Analytics — read access, and the correct property and data stream identified
- [ ] CMS or content export available, with its page count and export date recorded
- [ ] Crawler or backlink tool access available
- [ ] Every source above tested with one real query that returns rows. A successful
      authentication is not a working data source

## Scope

- [ ] Domains and subdomains in scope listed explicitly
- [ ] Markets and their URL structures listed
- [ ] Date window for the audit fixed and written down
- [ ] Pages or sections deliberately out of scope, and why

## Baseline capture

- [ ] Twelve-month performance baseline exported and stored with its date
- [ ] Index coverage snapshot taken
- [ ] Live `robots.txt` and every sitemap saved with a fetch date
- [ ] Content inventory exported

## Ground rules

- [ ] `DELIVERY_QUALITY_LEDGER.md` in place before the first deliverable
- [ ] Output location decided; nothing gets written into the reference data folders
- [ ] Agreed with the stakeholder: which findings need their decision versus which are
      yours to call. Record open decisions as they arise rather than assuming an answer
- [ ] Agreed who deploys changes and who verifies them afterwards
